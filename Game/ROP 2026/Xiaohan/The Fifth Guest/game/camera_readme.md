# Forensic Camera Module — Ren'Py Reusable Photography System

A modular camera/photography system for Ren'Py forensic education games. Players use a simulated camera to photograph evidence, with adjustable ISO, aperture, focal length, and zoom. Photos are scored across 4 dimensions (composition, exposure, sharpness, completeness) and stored in a photo album.

## 1. Module Overview

### What it does
- **Viewfinder UI**: Full-screen camera interface with adjustable ISO (100-800), aperture (F5.6-F16), focal length (50mm/105mm), and zoom
- **Photo Scoring**: Each photo is graded on composition, exposure, sharpness, and completeness (max 100 points, letter grade A+ to F)
- **Photo Album**: Browse all taken photos in a 6-per-page grid layout, click to view full-size
- **Depth of Field**: Aperture affects background blur (wide aperture = more blur, narrow = everything sharp)

### How it works
The entire camera system operates as **screen overlays** — it never uses `renpy.jump()`, `renpy.call()`, or `scene` changes. This means:
- The camera can be opened from ANY scene without breaking the game flow
- When closed, the player is back exactly where they were
- No label-based navigation, no flow disruption

## 3. Architecture: All-Overlay Design

```
┌─────────────────────────────────────┐
│  zorder 100: Camera Overlays        │  ← Viewfinder, Score, Album, Viewer
│  (modal, blocks everything below)   │
├─────────────────────────────────────┤
│  zorder 55-61: Inventory System     │  ← Toolbox, evidence box, item menus
│  (always accessible, above scenes)  │
├─────────────────────────────────────┤
│  zorder 50: Scene Overlays          │  ← e.g. injury close-up views
├─────────────────────────────────────┤
│  Base: Game Scene                   │  ← Whatever scene is currently shown
└─────────────────────────────────────┘
```

**Key principle**: Camera screens use `show screen` / `hide screen` ONLY. They never call `renpy.jump()`, `renpy.call()`, or change the scene. This preserves whatever the game was doing when the camera was opened.

### Important: Inventory zorder
For the camera to work from scene overlays (like injury close-up views at zorder 50), ALL inventory screens must have zorder > 50. Recommended values:

| Screen | zorder |
|--------|--------|
| `full_inventory` | 55 |
| `inv_buttons` | 56 |
| `toolboxpop` | 56 |
| `inventory` | 57 |
| `toolbox` | 57 |
| `close_inv` | 58 |
| Item menus | 59 |
| `inspectItem` | 60 |
| `characterSay` | 61 |
| **Camera overlays** | **100** |

## 6. Scoring Configuration

The scoring config JSON file controls how photos are evaluated.

### Scoring weights (per location)

Each location has 4 scoring categories that must total 100:

| Category | What it measures | Typical weight |
|----------|-----------------|----------------|
| `composition` | Subject position (X/Y) + zoom level | 25-30 |
| `exposure` | ISO correctness + aperture correctness | 25-30 |
| `sharpness` | Lens choice + focus quality (zoom accuracy) | 30-35 |
| `completeness` | Required elements (customizable) | 10 |

### Optimal settings

For each location, define the "perfect" camera settings:

| Setting | Description | Example |
|---------|-------------|---------|
| `lens` | Best lens for this subject | `"105mm"` for close-ups, `"50mm"` for wider shots |
| `aperture_index` | Index into aperture_group [F5.6, F8, F11, F16] | `1` = F8 |
| `iso_index` | Index into iso_group [100, 200, 300, 400, 800] | `1` = 200 |
| `zoom_optimal` | Best zoom level | `3.5` |
| `zoom_range` | Acceptable zoom range | `[3.2, 3.8]` |
| `composition.theme_x/y_optimal` | Best subject position (0.0-1.0) | `0.5` = centered |
| `composition.theme_x/y_range` | Acceptable position range | `[0.45, 0.55]` |

### Grade thresholds

```json
"grade_thresholds": {
    "A+": 95, "A": 90, "A-": 85,
    "B+": 80, "B": 75, "B-": 70,
    "C+": 65, "C": 60, "C-": 55,
    "D": 50, "F": 0
}
```

### Dev tool: Export current settings

While in the viewfinder, you can call `generate_current_settings_json()` from the Ren'Py console to export whatever settings you currently have as a JSON snippet. This helps you find the optimal settings for each location by manually positioning the camera where it looks best, then exporting.

## 7. Generating Aperture Images

The `generate_aperture_images.py` script creates depth-of-field (bokeh) effects for each photo location.

### Prerequisites

```bash
pip install Pillow numpy
```

### How it works

For each location, the script:
1. Loads the **base image** (the injury/evidence photo)
2. Loads a **mask** (white = subject/sharp, black = background/blurred)
3. For each aperture value, applies Gaussian blur to the background while keeping the subject sharp
4. Saves as `{location}-{aperture}.png`

| Aperture | Blur radius | Effect |
|----------|-------------|--------|
| F5.6 | 50 | Very blurry background (shallow depth of field) |
| F8 | 30 | Moderate blur |
| F11 | 12 | Slight blur |
| F16 | 0 | Everything sharp (deep depth of field) |

### Setup

1. **Edit the LOCATIONS dict** in the script to match your game:

```python
LOCATIONS = {
    "location_id": "source_image_filename.png",
    # Example:
    "knuckle1": "knuckle1.png",
    "desk_top": "desk_overview.png",
}
```

2. **Place base images** in `game/images/injury_screens/` (or change `INJURY_DIR` in the script)

3. **(Optional) Create masks** — see Section 8. If no mask is found, the script automatically creates a radial gradient (center sharp, edges blurry).

### Running

```bash
cd your_game_root/
python generate_aperture_images.py
```

Output:
```
[OK] Processing 'knuckle1'...
     -> knuckle1-5.6.png (blur=50)
     -> knuckle1-8.png (blur=30)
     -> knuckle1-11.png (blur=12)
     -> knuckle1-16.png (blur=0)
...
```

Images are saved to `game/images/camera/`.

### Adjusting blur intensity

Edit the `APERTURE_BLUR` dict:
```python
APERTURE_BLUR = {
    "5.6": 50,   # Increase for more blur
    "8":   30,
    "11":  12,
    "16":  0,    # Always 0 (fully sharp)
}
```

### Adjusting radial mask (no-mask fallback)

If you're not using custom masks, you can tune the auto-generated radial mask:
```python
def create_radial_mask(size, center_ratio=0.15, fade_ratio=0.35):
```
- `center_ratio=0.15` — 15% of the diagonal is fully sharp (increase = bigger sharp area)
- `fade_ratio=0.35` — Transition zone ends at 35% (increase = more gradual falloff)

## 8. Creating Custom Masks

Custom masks give the best results because you control exactly what stays sharp.

### How to create a mask

1. Open your base image in **Photoshop / GIMP / any image editor**
2. Create a new layer
3. Fill the entire image with **black** (= will be blurred)
4. Paint the subject area with **white** (= will stay sharp)
5. Use a **soft brush** along the edges for smooth transitions (gray = partial blur)
6. Save as PNG with the same dimensions as the base image

### Naming convention

```
Base image:  game/images/injury_screens/knuckle1.png
Mask image:  game/images/injury_screens/knuckle1_mask.png
```

For images with non-standard names:
```
Base image:  game/images/injury_screens/tattoo_close_base.png
Mask image:  game/images/injury_screens/tattoo_close_base_mask.png
```

### Mask format

- **White (255)** = Subject — stays perfectly sharp at all apertures
- **Black (0)** = Background — gets maximum blur at wide apertures
- **Gray (1-254)** = Transition — proportional blend between sharp and blurry
- **File format**: PNG, same dimensions as base image
- **Color mode**: Grayscale (the script converts automatically)

### Tips for good masks

- The subject outline should extend slightly beyond the actual subject (a few pixels) to avoid halo artifacts
- Use a soft brush (feathered edges) for natural transitions
- For objects with hair/fur/complex edges, use larger feathering
- The mask doesn't need to be pixel-perfect — even rough masks look much better than the radial fallback

### Recommended: Use remove.bg (Easiest Method)

[https://www.remove.bg/](https://www.remove.bg/) is the easiest way to create aperture images — **no script needed, no mask needed, all done on the website**.

#### Method A: Directly create aperture images on the website (Easiest)

1. Go to [remove.bg](https://www.remove.bg/) and upload your base image (e.g. `knuckle1.png`)
2. The site automatically cuts out the subject
3. Click **"Effects"**
4. Click **"Blur Background"**
5. Adjust the blur slider to the desired level
6. **Download** the result
7. Repeat steps 5-6 with different blur levels for each aperture:

| Aperture | Blur level on remove.bg | Save as |
|----------|------------------------|---------|
| F5.6 | High (lots of blur) | `knuckle1-5.6.png` |
| F8 | Medium | `knuckle1-8.png` |
| F11 | Low (slight blur) | `knuckle1-11.png` |
| F16 | No blur (use original image) | `knuckle1-16.png` |

8. Place all 4 images in `game/images/camera/`
9. Done! No script needed.

#### Method B: Download cutout, use our script to batch-generate (Automated)

If you have many locations and want to automate, you can download the cutout (PNG with transparent background) from remove.bg and let our script generate all aperture variants:

1. On remove.bg, after removing the background, **download the cutout PNG**
2. Save it as `game/images/injury_screens/{name}_cutout.png` (e.g. `knuckle1_cutout.png`)
3. Run `python generate_aperture_images.py`
4. The script will detect the cutout file, convert the transparent background to a mask, and generate all 4 aperture images automatically

### Quick mask in GIMP

1. Open base image -> Select By Color (or use free select tool for subject)
2. Select -> Grow (by 3-5 pixels)
3. Select -> Feather (by 10-15 pixels)
4. Edit -> Fill with white
5. Select -> Invert
6. Edit -> Fill with black
7. Flatten -> Export as `{name}_mask.png`

## 9. Inventory Integration Details

### How the camera connects to the inventory system

```
Toolbox                         Evidence Box
┌─────────┐                     ┌─────────┐
│ 📷      │ ← Use button        │ 🖼️      │ ← Expand button
│ Camera  │   calls              │ Images  │   calls
│         │   camera_open_       │         │   camera_open_
│         │   viewfinder()       │         │   album()
└─────────┘                     └─────────┘
```

- **Camera in toolbox**: "Use" button opens the viewfinder
- **Images in evidence**: "Expand" button opens the photo album

### How `current_photo_location` works

The camera needs to know WHAT to photograph. Before opening the viewfinder, your game must set `current_photo_location` to a valid location ID.

If `current_photo_location` is empty or not a registered location, the camera shows a notification: "Please click on an injury first, then use the camera."

## 10. Customization Options

### Change font
```python
camera_config.font = "YourFont.ttf"  # Must be in game/fonts/ or game/
```

### Change scoring config path
```python
camera_config.scoring_config_path = "my_custom_scoring.json"
```

### Custom completeness scorer
For game-specific completeness logic:
```python
def my_completeness_scorer(photo, location_config):
    # Your custom logic here
    score = 10  # out of location_config["scoring_weights"]["completeness"]
    feedback = "All elements documented."
    return score, feedback

camera_config.custom_completeness_scorer = my_completeness_scorer
```

### Change camera hardware settings
```python
camera_config.aperture_group = ["F2.8", "F4", "F5.6", "F8"]  # Different aperture values
camera_config.iso_group = [100, 200, 400, 800, 1600]          # Different ISO values
camera_config.focal_lengths = ["35mm", "85mm"]                  # Different lenses
camera_config.zoom_ranges = {
    "35mm": (0.5, 1.5),
    "85mm": (2.0, 3.5),
}
```

Note: If you change `aperture_group`, the image naming pattern changes accordingly. The viewfinder loads images as `camera/{location}-{aperture_number}.png` where `aperture_number` is the F-value without the "F" prefix.

## 11. Troubleshooting

### "could not find image. ('camera/-8.png')"
**Cause**: `current_photo_location` is empty when the camera opens.
**Fix**: Make sure your game sets `current_photo_location` to a valid location ID before the player can use the camera.

### Camera opens but shows nothing / black screen
**Cause**: Aperture variant images are missing.
**Fix**: Run `generate_aperture_images.py` to create them, or manually place images at `game/images/camera/{location}-{aperture}.png`.

### Inventory disappears when viewing injury close-up
**Cause**: Your injury close-up screen has a higher zorder than inventory screens.
**Fix**: Raise all inventory screen zorders above your scene overlay zorders (see Section 3 zorder table).

### Toolbox disappears after using camera
**Cause**: `hide_all_inventory()` is called before `camera_open_viewfinder()`.
**Fix**: In `toolbox_actions()`, the camera branch should NOT call `hide_all_inventory()`. Just call `camera_open_viewfinder()` and `return`.

### Score screen shows "Error: Scoring config not loaded"
**Cause**: `camera_scoring_config.json` is missing or has JSON syntax errors.
**Fix**: Verify the file exists in `game/` and is valid JSON. Use a JSON validator.

### Score screen shows "Error: Location 'xxx' not found in config"
**Cause**: The location ID used in code doesn't match the JSON config key.
**Fix**: Ensure `camera_config.register_location("xxx", ...)` matches the key in `camera_scoring_config.json`.
